# C1: NTRIP receive + RTCM3 validation (C++17)

A native ROS 2 C++17 executable `rtk_correction_bridge_node` subscribes to no rover control topics and publishes only `/rtk_correction_bridge/status`.

Supports opt-in NTRIP TCP/TLS receive, Basic auth, HTTP/ICY 200 header validation, bounded incremental RTCM3 parser and CRC-24Q validation, reconnect after disconnect, and default-disabled network activity. TLS is required by default with CA and hostname checks; plaintext requires deliberate opt-out.

**Important: NOT receiver injection:** No USB/serial output, no GGA uplink, no RTK acceptance claim, no correction-age trust signal, no PX4-in commands. Production direct RTCM serial sink, exclusive lock, NMEA GGA, receiver verified correction age, TLS/RTCM caster integration tests, and lifecycle tests remain pending. No motion or spray authorization.

Do not enable `receive_enabled` on deployment without reviewing NTRIP caster network credentials, mountpoint and data governance. Password supplied as a ROS parameter may be visible through ROS parameter interfaces, shell history or process arguments; prefer protected configuration and credentials management before production. This C1 implementation is a candidate requiring integration verification.

## C2 direct serial RTCM transport

Added POSIX byte-exact serial write with termios (115200/230400/460800), advisory exclusive flock, poll write deadline, and fail-close on incomplete frame. Disabled by default; requires receive_enabled, serial_injection_enabled, serial_commissioned, and serial_device together. This is **not field-commissioned**. A ROS parameter flag is not a hardware safety interlock. Do not enable on production rover before verifying COM2 wiring, permission, correction source exclusivity, port speed and receiver behavior. No trusted GNSS RTK-FIX/age evidence is generated by this package.

## C4: Receiver-reported correction age — independent read-only diagnostic

A separate opt-in read-only receiver serial adapter parses checksummed NMEA GGA lines. NMEA GGA differential-age field (13) is accepted only with RTK FIX/FLOAT quality (4/5), a valid checksum, and a bounded numeric age. The status reports age plus host monotonic elapsed time, or `unavailable` after one second. Configure `receiver_age_observe_enabled=true`, `receiver_age_device`, and `receiver_age_baud` only after receiver output wiring is validated. The age serial port MUST NOT be the same as the RTCM injection port; both use exclusive locks.

This is **diagnostics only**, not yet a trusted feed to `NativeRtcmAgeGuard` in mission_manager. Do not infer receiver authenticity from a ROS status topic alone. PX4 v1.17 SensorGps has no differential correction-age field. Mission motion, spray, and automatic resume remain disabled. Hardware verification and trust-boundary commissioning remain pending.
